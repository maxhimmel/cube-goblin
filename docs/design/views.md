# Workbench views

How the workbench is laid out, by what the user is doing. Agreed with the user on 2026-11-09. Each view is built under the ticket named in its row.

## One workspace

Every view shares a top bar: brand (the cube's name, with a cube switcher beside it, [T-057](../tickets/T-057-multiple-cubes.md), [T-061](../tickets/T-061-host-parity.md)), view switcher, one save state, "+" for the add panel, import and export ([T-059](../tickets/T-059-import-export-formats.md)), and settings ([T-045](../tickets/T-045-top-bar-and-settings.md)); the share doc keeps its review controls there instead. Settings edit the cube folder's `cube.config.json`. A card opens in a detail pane that slides in from the right over any view and keeps its own URL, so there is no separate card page.

## The card at a glance

Wherever cards are stacked or small, each one shows its name, mana cost, and color without a hover. On desktop, hovering shows the whole card; on touch, a tap opens the detail pane.

## Card types

The type list lives in `TYPE_COLUMNS` (`packages/cube/src/stats.ts`). A card shows under every type on its front face, so an Artifact Creature sits in both the Artifact and the Creature columns ([T-019](../tickets/T-019-card-types-overlap.md)). Sorting uses the first match only. Mechanic groups such as "makes tokens" are [function](../GLOSSARY.md#function) tags ([T-022](../tickets/T-022-functions-as-tags.md)), not Forge columns.

## Look

Palette from the binder direction (navy pages, violet accent); cards lift and tilt on hover. Forge is the reference look: its panels, uppercase headings, segmented controls, chips, and menus are the shared styles in `apps/web/src/ui.css`, and font sizes come from the `--fs-*` type scale, tunable live in `pnpm dev` ([T-050](../tickets/T-050-visual-system.md)). Screenshots of the three explored directions are not kept; the CSS that ships is the source of truth.
