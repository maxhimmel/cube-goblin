# Workbench views

How the workbench is laid out, by what the user is doing. Agreed with the user on 2026-11-09. Each view is built under the ticket named in its row.

## One workspace

Every view shares a top bar: brand, view switcher, one save state, "+" for the add panel, and settings ([T-045](../tickets/T-045-top-bar-and-settings.md)); the share doc keeps its review controls there instead. Settings edit `cube.config.json`. A card opens in a detail pane that slides in from the right over any view and keeps its own URL, so there is no separate card page.

## The card at a glance

Wherever cards are stacked or small, each one shows its name, mana cost, and color without a hover. On desktop, hovering shows the whole card; on touch, a tap opens the detail pane.

## Card types

The type list lives in `TYPE_COLUMNS` (`packages/cube/src/stats.ts`). A card shows under every type on its front face, so an Artifact Creature sits in both the Artifact and the Creature columns ([T-019](../tickets/T-019-card-types-overlap.md)). Sorting uses the first match only. Mechanic groups such as "makes tokens" are [function](../GLOSSARY.md#function) tags ([T-022](../tickets/T-022-functions-as-tags.md)), not Forge columns.
